PROJECT IDEA DOCUMENTATION
============================

Project Title:
AI-Powered Daily Sales Intelligence & Business Reporting System

1. PROJECT OVERVIEW
-------------------
This project is an end-to-end Sales Intelligence system that converts raw company sales
data into useful business information and automatically explains what is happening in
the business.

The system is designed for a business owner or manager who may not have time to study
large Excel/CSV files or interpret multiple dashboards every day.

Instead of only displaying graphs, the system analyzes sales, revenue, cost, profit,
customers, products, regions, discounts and trends, identifies important changes or
problems, and produces a simple daily business report.

The report can be shown inside the application and sent to the manager through email.
WhatsApp notification/report delivery can be added as a later feature.

2. PROBLEM STATEMENT
--------------------
Businesses generate large amounts of transactional data every day. Although dashboards
can display charts and KPIs, a non-technical manager may still have difficulty
understanding:

- What happened today?
- Did revenue increase or decrease?
- Did profit improve or fall?
- Which products are performing well?
- Which regions are underperforming?
- Are new customers increasing?
- Are discounts reducing profit?
- Is there anything unusual that requires attention?
- What should the manager focus on?

Usually, a person has to manually analyze the data and explain the results.

This creates dependency on analysts, consumes time, and makes daily decision-making slower.

3. PROPOSED SOLUTION
--------------------
Build an automated Sales Intelligence pipeline.

The system will:

1. Receive raw sales data.
2. Clean and validate the data.
3. Store/process the data.
4. Calculate important business KPIs.
5. Compare current performance with previous periods.
6. Detect important changes, trends and warning conditions.
7. Generate an understandable business summary.
8. Use an LLM to convert calculated facts into a natural-language daily report.
9. Display the information through a dashboard.
10. Send the report through email.
11. Optionally support WhatsApp notifications in a later stage.

4. MAIN IDEA
------------
The key difference from a normal dashboard is:

NORMAL DASHBOARD:
Raw Data -> Charts -> Manager interprets everything

OUR SYSTEM:
Raw Data -> Analysis -> Important Findings -> AI Explanation -> Manager

The LLM will NOT be responsible for calculating business numbers. Python/SQL will
calculate the facts first. The LLM will receive verified metrics and findings and
convert them into an easy-to-understand explanation.

9. BUSINESS RULES / ALERTS
---------------------------
The first version can use transparent rule-based logic.

Examples:

- If revenue decreases significantly -> Revenue Warning
- If profit decreases while revenue increases -> Profitability Warning
- If a region falls significantly -> Regional Alert
- If discount increases and margin falls -> Discount Warning
- If a product suddenly drops in sales -> Product Alert
- If new customers fall -> Customer Acquisition Alert

This makes the system explainable.

Later, machine-learning-based anomaly detection can be added.

10. ROLE OF THE LLM
-------------------
The LLM is NOT the primary analytics engine.

Python and SQL will calculate verified facts.

Example facts sent to the LLM:

Revenue change: +12.4%
Profit change: +8.2%
Gujarat revenue change: -11%
Electronics margin change: -4.3%
Top product: Laptop Pro

The LLM converts these facts into a concise business report.

This reduces the risk of the LLM inventing calculations.

11. NLP REQUIREMENT
-------------------
A transformer/NLP model is NOT required for the first version.

The initial system mainly works with structured numerical/tabular data.

calculate_region_performance()

------------------------------
Create rules that identify important situations.

Example:

    create_revenue_alert()

if revenue_change > 0 and profit_change < 0:
    create_profitability_alert()

if discount_change > threshold and margin_change < threshold:
    create_discount_alert()

Output:
Structured findings/alerts.

PHASE 6 - DASHBOARD
-------------------
Build the dashboard using the calculated metrics.

Output:
Interactive business dashboard.

PHASE 7 - LLM REPORT GENERATION
-------------------------------
Send only verified metrics and findings to the LLM.

Prompt structure:

"You are a business analyst. Based only on the verified metrics below,
write a concise daily business report. Do not invent numbers."

Then provide the metrics.

Output:
Human-readable daily report.

PHASE 8 - EMAIL AUTOMATION
---------------------------
Create an automated email containing the daily report.

Output:
Manager receives the report without manually opening the dataset.

PHASE 9 - SCHEDULING
--------------------
Schedule the pipeline to execute automatically every day.

Output:
Fully automated daily reporting system.

PHASE 10 - DEPLOYMENT
---------------------

23. SYNTHETIC DAILY SALES DATA GENERATOR
----------------------------------------
To demonstrate the live/daily-updating nature of the project without requiring
access to a real company's internal database, the system will include a
Synthetic Daily Sales Data Generator.

The generator will create realistic new sales transactions for each simulated
business day using patterns learned from the existing two-month historical
dataset.

The generator will NOT simply create arbitrary random numbers. It will preserve
realistic relationships between:

- Products
- Categories
- Regions
- Customers
- Quantities
- Prices
- Discounts
- Revenue
- Cost
- Profit
- Profit Margin
- Sales channels
- Payment methods

The overall flow will be:

Historical Dataset
        |
        v
Historical Pattern Analysis
        |
        v
Synthetic Daily Data Generator
        |
        v
Generate New Daily Transactions
        |
        v
Append Transactions
        |
        v
KPI + Alert Engine
        |
        v
Dashboard + AI Daily Report

24. PYTHON SCRIPT: DAILY_DATA_GENERATOR.PY
------------------------------------------
A Python script named:

daily_data_generator.py

will be developed as part of the project.

The script will:

1. Load the cleaned historical sales dataset.
2. Inspect historical distributions.
3. Generate a realistic number of new orders for a simulated day.
4. Create unique Order_ID values.
5. Generate/select customer IDs and customer types.
6. Select products according to historical product patterns.
7. Generate realistic quantities.
8. Use realistic prices based on historical data.
9. Generate discounts within realistic ranges.
10. Calculate Revenue.
11. Calculate Cost.
12. Calculate Profit.
13. Calculate Profit_Margin.
14. Assign region, city, sales channel and payment method.
15. Set the new Order_Date.
16. Validate the generated records.
17. Append the new transactions to the main dataset/database.

During development, the script can be executed with:

python daily_data_generator.py

Later, this script will be executed automatically by a scheduler.

25. REALISTIC DATA GENERATION
-----------------------------
The generator will use the historical dataset to estimate realistic distributions.

For example, if historical data shows that:

- Electronics represents a certain percentage of orders
- Maharashtra contributes a certain percentage of sales
- Typical quantity is 1-5 units
- Discounts are usually between certain ranges
- Certain products sell more frequently

the generator will preserve those patterns while introducing controlled variation.

Business relationships will also be preserved.

For example:

Revenue = Quantity × Unit Price after discount

Profit = Revenue - Cost

Profit Margin = Profit / Revenue × 100

This is important because the generated data must behave like a real business
dataset and should be suitable for testing analytics, alerts and AI reports.

26. SIMULATED LIVE DATA MODE
----------------------------
The project will support a simulated live-data mode.

The historical dataset acts as the starting point.

For example:

Day 1:
Historical data + August 16 transactions

Day 2:
Historical data + August 16 + August 17 transactions

Day 3:
Historical data + August 16 + August 17 + August 18 transactions

After each update, the analytics pipeline will run again.

This allows the project demonstration to show a continuously growing dataset
and a dashboard/report that changes as new transactions arrive.
